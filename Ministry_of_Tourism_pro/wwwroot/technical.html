Architecture Overview

Presentation Layer — MVC Views
Razor .cshtml views served by ASP.NET Core controllers. Role-specific dashboards for HotelOwner, Admin, Commissioner, and SystemAdmin.
Application Layer — Controllers + Services
Business logic separated into IHotelService, SharedHelpers, and domain controllers. DTOs used for all data transfer.
Data Layer — CNET V7 REST API
All database reads/writes go through an internal REST API (GetFilterData, GetFilterDynamic, SendReqAsync). No direct DB access from the web app.
Persistence — SQL Server + FTP
Structured hotel and infrastructure data in SQL Server. Binary attachments stored on a dedicated FTP server and referenced by URL.
The web application never connects directly to SQL Server. All data access is brokered through the CNET V7 API layer, ensuring data integrity and a single point of change.

Security Guarantees

Role-Based Access Control
Four roles: HotelOwner, Admin, Commissioner, SystemAdmin. Every action is decorated with [Authorize(Roles=...)]. Cross-role access returns 403.
Secure Cookie Authentication
ASP.NET Identity issues HttpOnly, SameSite=Strict session cookies. Sessions expire on browser close by default.
Anti-Forgery Tokens (CSRF)
All state-changing POST endpoints are protected with ASP.NET's built-in CSRF anti-forgery token validation.
HTTPS Enforcement
IIS redirects all HTTP to HTTPS. TLS certificates are bound to the site. UseHsts() is active in production.
No Direct DB Access
The web layer holds no SQL connection strings. All queries route through CNET V7 API, isolating SQL Server from the public-facing app.
Input Validation & DTOs
All incoming data is bound through strongly-typed DTOs with model state validation, preventing injection and binding attacks.
Hashed Passwords
ASP.NET Identity uses PBKDF2 with HMAC-SHA256. Plaintext passwords are never stored or logged.
Audit Logging
Approval, rejection, and critical state changes are captured in server logs with timestamps and user identity.

IIS Deployment

Published as a self-contained ASP.NET Core 6 app hosted on Windows Server with IIS 10. The CNET V7 API runs as a separate IIS site on the same server network.
1
Install Prerequisites
Install .NET 6 Hosting Bundle on the Windows Server. Enable IIS with ASP.NET Core Module (ANCM).
2
Publish the Application
Run dotnet publish -c Release -o ./publish. Copy output to the server's site root (e.g. C:\inetpub\tourism-portal).
3
Configure IIS Application Pool
Create an App Pool with No Managed Code (.NET CLR Version). Assign it to the website with sufficient folder permissions.
4
Set Production appsettings.json
Update appsettings.json with production API base URL, FTP credentials, and SMTP settings before deployment.
5
Bind HTTPS Certificate
In IIS Site Bindings add HTTPS on port 443. Assign the TLS certificate. Enable HTTP → HTTPS redirect via URL Rewrite module.
6
Verify & Smoke Test
Login with each role, verify CNET V7 API connectivity, and check the Logs/ folder for startup errors.
